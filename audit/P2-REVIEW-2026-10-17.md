## 实际修复

1. `integrity.observation_time` 按记录类型取得可比较的来源时间：quote 使用有效、有限、正数的 `regularMarketTime`，日线核对 `asOf` 和最后实际 bar，index 使用 date，FX 使用 asOf，ratio 使用与当前价格配对的日期。`merge` 拒绝缺失/无效或倒退的观察时间，保留旧记录对象与原 receivedAt；同日分钟级倒退和跨日倒退都覆盖。Yahoo quote 适配器不再返回无有效时间的记录。估值 provenance 同时保留来源时间戳与收到时间。
2. 月份标签不作为收盘观察日期。腾讯月线保留 periodDates，再从独立 raw day 响应取得配对的日期与价格，存入 current/asOf，并用该价格作为当前月值。不能证明日线日期时保持 current/asOf 为空；Yahoo 月区间时间戳仅保留作 periodTimestamps，不伪装为当前收盘时间。ratio 两方必须同日、与页面 asOf 一致、收到时间及行情日期仍有效、当前价格与序列一致，才进入计算。否则 ratio=null，沿用冻结 UI 的不可用状态。同日缓存可在原 36 小时窗口内使用；新回执不能挽救旧日期。
3. 实质指纹递归排除纯采集 receivedAt，仍保留原有 generatedAt/today 排除规则；不会删除 DATA、缓存或审计中的回执。价格、观察时间、来源、派生有效性、财务核验日期及页面代码变化仍改变指纹。回执过期导致数据有效性变化时也改变指纹。

## 网络与权限的可证结论

- 当前运行约束明确为 workspace-write、network restricted、approvals_reviewer=auto_review；shell 暴露 `sandbox_permissions=require_escalated`。runtime 没直接给出 approval_policy 的具体字符串，不能臆测为 on-request 或 never；本轮实际成功证明相关命令审批类别可用。

- `git ls-remote` 经正常审核确认远端分支等于基准，见 remote-confirmed。初始本地确实没有 remote；本轮配置精确 origin。
- 添加 remote 的首次获准命令碰到 Git dubious ownership：仓库由 CodexSandboxOffline 创建，获准进程以 10750 运行。没有照报错建议修改全局 safe.directory；后续获准命令仅使用 `git -c safe.directory=<此准确仓库路径>` 临时信任已经核验的用户指定目录，随后添加成功。remote-before-push 日志的 origin 不存在是该首次添加失败的后果，不是新的网络或凭据拒绝。
